### User Story 2: _Datenbankverschlüsselung für Patienten-, Behandlungs- und Pflegedaten_

**Als Heimleiter
möchte ich, dass alle sensiblen Patientendaten sicher verschlüsselt gespeichert und verarbeitet werden,
damit personenbezogene Informationen vor unbefugtem Zugriff geschützt sind und Datenschutzanforderungen erfüllt werden.**


**Akzeptanzkriterien**

| Nr. | Kriterium                                                                                                                                                                                                                                                                         |
|-----|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| A_1 | Alle Patienten-, Behandlungs- und Pflegedaten werden vor dem Speichern mit mindestens AES-256 verschlüsselt.                                                                                                                                                                      |
| A_2 | Daten werden ausschließlich für die Anzeige oder Verarbeitung im Anwendungsspeicher entschlüsselt.                                                                                                                                                                                |
| A_3 | Neu angelegte oder geänderte Daten werden automatisiert verschlüsselt, bevor sie an die Datenbank übergeben werden.                                                                                                                                                               |
| A_4 | Ver- und Entschlüsselungsschlüssel dürfen: nicht im Quellcode,nicht in SQL-Skripten, nicht in Konfigurationsdateien im Klartext, und nicht direkt in der Datenbank gespeichert werden.                                                                                            |
| A_5 | Bei fehlgeschlagener Ver- oder Entschlüsselung: erhält der Benutzer ausschließlich eine generische Fehlermeldung, werden keine technischen Details offengelegt, wird der Vorfall sicher protokolliert.                                                                            |
| A_6 | Alle Änderungen an verschlüsselten Daten werden anonymisiert protokolliert. Das Log enthält: WAS geändert wurde, WANN die Änderung erfolgte. Das Log enthält nicht: WER die Änderung vorgenommen hat, keine entschlüsselten Inhalte, keine Schlüssel oder technische Geheimnisse. |
| A_7 | Die Datenbank speichert am Datensatz: welcher Benutzer die letzte Änderung vorgenommen hat, sowie den Zeitpunkt der Änderung. Diese Information darf nicht Bestandteil des anonymisierten Änderungslogs sein.                                                                     |
| A_8 |     Die Ver- und Entschlüsselung erfolgt innerhalb der DAO-/Persistenzschicht, ohne dass die Fachlogik Verschlüsselungsoperationen direkt implementieren muss.                                                                                                                                                                                                                                                                              |

**Tasks**

| Nr. | Task                                                                                                                                                          |
|-----|---------------------------------------------------------------------------------------------------------------------------------------------------------------|
| T_1 | Zentralern Encryption Service Entwickeln mit zuhilfenahme von AES-256                                                                                         |
| T_2 | Integration eines Key-Management Konzepts und sichere Schlüsselverwaltung                                                                                     |
| T_3 | Automatische Verschlüsselung vor INSERT und UPDATE, Automatische Entschlüsselung nach SELECT                                                                  |
| T_4 | Datenbankschema Anpassen, sodass Verschlüsselte Daten gespeichert werden können                                                                               |
| T_5 | Logging implementieren nach Akzeptanzkriterien                                                                                                                |
| T_6 | Fehlerbehandlung Implementieren; technische Fehler intern behandeln, nutzerfreundliche Fehlermeldungen anzeigen, sicherheitsrelevante Vorfälle protokollieren |



**Testfälle**

**TF1: Datenintegrität nach Verschlüsselung**

| |                                                                                                        |
|---|--------------------------------------------------------------------------------------------------------|
| **Vorbedingung** |                                                                                                        |
| **Testschritte** | - Datensatz anlegen <br/>- Daten in der DB prüfen  <br/>- Datensatz Abrufen <br/>- Inhalte vergleichen |
| **Erwartetes Ergebnis** | Daten liegen Verschlüsselt in der DB vor, Entschlüsselte Daten entsprechen den ursprünglichen Daten    |

**TF2: Keine Klartextdaten in der Datenbank**

| |                                                                   |
|---|-------------------------------------------------------------------|
| **Vorbedingung** |                                                                   |
| **Testschritte** | - Datensatz speichern <br/>- Direkte Datenbankabfrage durchführen |
| **Erwartetes Ergebnis** | keine sensiblen Daten im Klartext sichtbar                        |

**TF3: Sichere Fehlerbehandlung**

| |                                                                          |
|---|--------------------------------------------------------------------------|
| **Vorbedingung** |                                                                          |
| **Testschritte** | Fehlerhaften Schlüssel Simulieren und Datensatz abrufen                  |
| **Erwartetes Ergebnis** | Generische Fehlermeldung für Nutzer, Interne Protokollierung des Fehlers |

**TF4: Logging ohne Sensible Daten**

| |                                                                                            |
|---|--------------------------------------------------------------------------------------------|
| **Vorbedingung** |                                                                                            |
| **Testschritte** | Datensatz ändern, Logs Prüfen                                                              |
| **Erwartetes Ergebnis** | Log enthält Änderungstyp, Zeitstempel. Log enthält NICHT: Nutzer, Klartextdaten, Schlüssel |

**TF5: Speicherung der letzten Bearbeitenden Person**

| |                                                                                                          |
|---|----------------------------------------------------------------------------------------------------------|
| **Vorbedingung** |                                                                                                          |
| **Testschritte** | Nutzer ändert Datensatz, Datenbankeintrag prüfen                                                         |
| **Erwartetes Ergebnis** | Letzter Bearbeiter ist korrekt in der Datenbank gespeichert, information erscheint nicht im Änderungslog |

### User Story 3: Login System


> Als Pflegekraft
> möchte ich mich mit Benutzername und Passwort anmelden können,
> um Patientendaten vor unbefugtem Zugriff zu schützen.****

**Akzeptanzkriterien**

| Nr. | Kriterium                                                            |
|-----|----------------------------------------------------------------------|
| A_1 | Benutzer können sich mit Benutzername und Passwort anmelden          |
| A_2 | Falsche Login-Daten erzeugen eine Fehlermeldung                      |
| A_3 | Passwörter werden verschlüsselt gespeichert                          |
| A_4 | Nicht angemeldete Benutzer können nicht auf Patientendaten zugreifen |
| A_5 | Nach 15 Minuten Inaktivität erfolgt ein automatischer Logout         |
| A_6 | Ein Super User kann Passwörter zurücksetzen                          |

**Tasks**

| Nr. | Task                                               |
|-----|----------------------------------------------------|
| T_1 | Login-Maske erstellen                              |
| T_2 | Benutzerverwaltung um Login-Daten erweitern        |
| T_3 | Passwort-Verschlüsselung implementieren            |
| T_4 | Zugriffsschutz für Patientendaten einbauen         |
| T_5 | Automatischen Logout implementieren                |
| T_6 | Funktion zum Zurücksetzen von Passwörtern ergänzen |

**Testfälle**

**TF1: Erfolgreicher Login**

|                         |                                               |
|-------------------------|-----------------------------------------------|
| **Vorbedingung**        | Benutzer existiert                            |
| **Testschritte**        | Richtigen Benutzernamen und Passwort eingeben |
| **Erwartetes Ergebnis** | Benutzer wird erfolgreich angemeldet          |

**TF2: Falsches Passwort**

|                         |                            |
|-------------------------|----------------------------|
| **Vorbedingung**        | Benutzer existiert         |
| **Testschritte**        | Falsches Passwort eingeben |
| **Erwartetes Ergebnis** | Fehlermeldung erscheint    |

**TF3: Zugriffsschutz**

|                         |                               |
|-------------------------|-------------------------------|
| **Vorbedingung**        | Benutzer ist nicht eingeloggt |
| **Testschritte**        | Patientenübersciht öffnen     |
| **Erwartetes Ergebnis** | Zugriff wird verweigert       |

**TF4: Automatischer Logout**

|                         |                                      |
|-------------------------|--------------------------------------|
| **Vorbedingung**        | Benutzer ist eingeloggt              |
| **Testschritte**        | 15 Minuten keine Aktivität           |
| **Erwartetes Ergebnis** | Benutzer wird automatisch ausgeloggt |

**TF5: Passwort zurücksetzten**

|                         |                                       |
|-------------------------|---------------------------------------|
| **Vorbedingung**        | Super User ist angemeldet             |
| **Testschritte**        | Passwort eines Benutzers zurücksetzen |
| **Erwartetes Ergebnis** | Neues Passwort wird gespeichert       |

**TF6: Passwort-Zurücksetzung ohne Super User Rechte**

|                         |                                                                           |
|-------------------------|---------------------------------------------------------------------------|
| **Vorbedingung**        | Benutzer ist kein Super User                                              |
| **Testschritte**        | Versuch, das Passwort eines anderen Benutzers zurückzusetzen              |
| **Erwartetes Ergebnis** | Passwort kann nicht zurückgesetzt werden und eine Fehlermeldung erscheint |
